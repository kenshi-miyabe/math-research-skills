# 数学論文のVerification Notes

再確認に時間がかかる根拠・依存関係・未確認事項を，後から追える記録として残す．AIの判断やVerification Notes自体を，数学的正しさの認証としない．

## 不可欠な制約

- 読んでいない原稿・原文の引用，書誌情報，導出，未実施の計算結果を作らない．未入手・未確認・誤りの疑い・確定した反例を分ける．
- 証明，sanity check，反例探索を区別する．AIの賛同や反例が出なかったことを証明の代わりにしない．
- 誤りを見つけたら原稿側の修正が必要な箇所と理由を伝える．依頼範囲を超えて本文を黙って変更せず，記録だけ直して解決済みとしない．
- 文章改善は `SUGGEST`，現在の正しさに関わる未解決事項は `TODO`，一般化等の研究課題は `Open problems` と分ける．
- 同じ文脈で直前に執筆・編集した証明を確認する場合は，会話を継承しない新しいサブエージェントに対象原稿と規則だけを渡し，確保できなければ `Log` に記す．

## 進め方

1. 対象の原稿・主張label・版を特定し，既存の記録を確認する．Master Expositionと投稿原稿を自動的に同一視しない．writing・reviewが `to_verify.md` に記録した候補を確認し，報告にだけ残る候補があれば重複を避けて追記し，検証と処理結果の記録を行う．
2. `references/verification-checks.md` から関係する観点を選び，原文・導出・独立な計算などで根拠を調べる．自明な箇所までカード化しない．
3. カードを作成・更新するときは `references/evidence-cards.md` に従う．未着手候補，未解決事項，依存関係と改訂の影響を追跡する．
4. 作成・更新した記録，得られた根拠，未解決事項，未入手資料，実施した確認を簡潔に報告する．

## 出力

既存のプロジェクト形式を優先する．新規作成では `templates/verification-layout.md` と `templates/card.md` を使う．LaTeXでは `templates/card.tex` と `assets/verification.sty` の実在するマクロだけを用いる．

対象指定がなければ現在の原稿と既存記録を探し，主結果を支える重要箇所から着手する．原稿が利用できない場合は内容を創作せず，必要なら空のテンプレートだけを準備する．
