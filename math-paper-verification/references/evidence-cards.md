# Evidence cardの記録と更新

## カードを作る対象

再確認に時間がかかる根拠，壊れやすい接続，文献との対応，再利用できる計算・反例を記録する．
自明な適用や数秒で追える計算，文章改善だけの項目はカード化しない．既存カードを調べ，重複を避ける．
原則1カード1ファイルとし，IDは数学的内容に基づく恒久名にする．節番号や配置変更でIDを変えない．

## 欄

| 欄 | 要件 |
| --- | --- |
| Target | 必須．原稿の対象labelと，確認したファイル・版を特定する |
| Paper lines | 必須．対象の原稿から必要な箇所を逐語コピーする．言い換えや記号の修正をしない |
| Expanded step | C3では原則必須．欠けた計算・推論を根拠付きで展開する |
| Locator | C1/C2で必須．原文の文献または内部label，参照箇所と実際に読んだ版を特定する |
| Source text | C1/C2で必須．使う主張を原文から逐語コピーする．未入手なら `[TO FILL]` と必要な確認を記す |
| Gap | C1/C2で必須．引用元が与えるものと必要な結論との差，埋める議論または障害を記す |
| Log | 必須．日付と，発見した内容・根拠・変更を具体的に記す．「確認した」だけで済ませない |

必要時だけ `Where the hypotheses are used`，`Notation map`，`Dependencies`，`Interface check`，
`Tests`，`Not settled`，`Open problems` を加える．接続が複雑なら，要求条件・引用元の結論・
現在の対象での照合・未確認事項を整理する．同じ内容を複数欄に重複させない．
`Dependencies` には前提となるlabel・card ID・文献を記し，単なる参考と区別する．

## 候補と中央管理

- 未着手候補は `to_verify.md` の `Active candidates` に対象・分類・疑問・記録する価値・次の確認を記し，`candidate` とする．候補だけで確認済みとしない．
- 処理後は `Resolved candidates` に日付，`card-created` または `rejected`，card IDや統合・移動先，理由を残す．
- `index.md` で原稿labelとcard IDを対応づける．記号一覧は必要な場合だけ作る．

| マーカー | 扱い |
| --- | --- |
| TO VERIFY | 未着手の候補．証拠や解決済みを意味しない |
| TODO | 現在の正しさに関わる未解決事項．cardの `Not settled` と中央TODOを同期する |
| TO FILL | 原文・書誌情報など必要な資料が未入手・未確認 |
| SUGGEST | 説明・構成だけの改善案．correctness cardを作らない |
| Open problems | 現在の正しさを妨げない一般化・研究課題．関連cardと中央一覧を結びつける |

## 改訂と解決の追跡

- `Paper lines` と現在の本文を比較する．一致しても，依存する定義・補題・文献の版が変われば再確認する．
- 影響するcardから下流をたどり，根拠が未確認の間は `Not settled` と中央TODOに残す．依存記録にないことだけで影響なしと判断しない．
- 解決したら根拠と確認した版を `Log` に残し，未解決欄と中央TODOの両方を更新する．依存元の誤りで証明が使えなくなることと，下流の結論が偽であることを区別する．
- 再利用価値のある失敗は，試した方針・仮定・障害・再検討条件を `Log` に残す．本文から削除された結果の有用な証拠も，削除理由を記して保持する．

原稿や原文がなく必須の逐語欄を埋められない場合は，捏造せず作成を保留するか，未入手であることを明示した未完成の記録とする．
AI作成の記録を採用する際は，人間が原文の引用箇所・主要な展開・実行結果を確認する．逐語引用は作業上必要な範囲とし，公開・再配布時の権利に留意する．
