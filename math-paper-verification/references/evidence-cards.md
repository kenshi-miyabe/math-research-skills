# Evidenceの記録と更新

## 記録する単位

再確認に時間がかかる根拠，壊れやすい接続，文献との対応，再利用できる導出・計算・反例をカードにする．自明な適用，数秒で追える計算，文章改善だけの項目はカード化しない．原則1カード1ファイルとし，数学的内容に基づく恒久IDを使う．配置や分類の変更だけでIDを変えない．
既存の記録・コード・報告への参照で足りれば再掲しない．以下の情報が追えれば既存の書式でよい．未実施の方法の空欄を増やさず，全項目に表やカードを要求しない．

## カードの欄

| 欄 | 記録する内容 |
| --- | --- |
| Target | 原稿のlabel・ファイル・版と検証範囲．例：`paper.tex @ abc1234`．未コミットの変更を含むなら保存版や差分も特定する |
| What | V1–V5から該当する対象（複数可）と，具体的に調べる問い |
| How | 実施したM1–M4（複数可）．予定と実施済みを区別する．形式検証結果への参照はEvidenceに置き，検証方法として数えない |
| Paper lines | 対象の主張・証明箇所を原稿から必要な範囲で逐語コピーする．言い換え・記号修正をしない |
| Evidence | 実施した作業と再検証可能な根拠．以下の既存欄や保存先への参照を用いてよい |
| Result | 下記の4状態，その判定範囲・理由．未確認部分・限界は該当欄に記す |
| Log | 日付，発見・変更・判断の根拠．「確認した」だけで済ませない |

これらを最小の追跡情報とし，次の詳細欄は内容に応じて選ぶ．同じ根拠を `Evidence` と詳細欄に二重に書かない．

- `Expanded step`：非自明な省略計算や別導出を根拠付きで展開する．別証明は証明できた範囲を示す．
- `Locator`・`Source text`・`Gap`：内部・外部依存の適用を検証する場合，原文のlabelまたは文献・定理番号・版・ページ，必要な主張の逐語引用，適用先との差と埋める議論・障害を記す．すぐ追える内部参照は保存版の該当箇所への参照で重複引用を省ける．原文未入手なら `[TO FILL]` と必要な確認を示す．
- `Where the hypotheses are used`・`Notation map`・`Interface check`：仮定の使用，記号の対応，要求条件と引用元の結論・対象での照合が複雑な場合に使う．`Gap`等と重複させない．
- `Dependencies`：前提となるlabel・card ID・外部文献を単なる参考と区別する．重要な外部依存の確認状況・未確認部分・追跡を止めた理由，別証明と元の証明の共通依存を示す．
- `Tests`：実験・探索の方法，範囲，条件，結果と限界，必要なコード・seed・出力への参照．価値のある失敗は障害・使用した仮定・再検討条件も残す．
- 外部の形式検証結果は `Evidence` に保存先・報告・コードの版・対象宣言への参照を置く．詳細は下記の「形式検証結果の参照」に従い，同じ情報を複製しない．
- `Not settled`：未確認事項と次の確認．対象範囲外と，現在の正しさに関わる未解決事項を区別し，後者は中央TODOと同期する．
- `Open problems`：現在の正しさを妨げない一般化や探索課題．関連カードと中央一覧を結ぶ．
- 独立再検証を行った場合は `Log` 等に担当・方法，対象版・範囲，渡した情報・先の判定を知っていたか，根拠・不一致・共有依存・限界を記す．報告の保存先を参照してよい．

原稿がなく逐語欄を埋められない場合は作成を保留するか，未入手と明示した未完成の記録にする．AI作成の記録の採用時は人間が引用・主要な展開・実行結果を確認する．逐語引用は作業に必要な範囲とし，公開・再配布時の権利に留意する．

## 結果と確認範囲

| Result | 意味 |
| --- | --- |
| 確認済み | 明示した対象・版・範囲について，選んだ手段による根拠が得られ，その範囲の確認課題が解消した |
| 部分的に確認済み | 対象範囲の一部は確認したが，残る部分がある．確認した部分と残りを示す |
| 問題あり | 誤った推論，適用条件の欠落，反例等，具体的な問題がある．根拠と確定度を示し，結論の偽と証明の欠陥を区別する |
| 未確認 | 必要な確認をしていない，資料未入手，改訂の影響で現在の版に根拠を適用できない等 |

確認済みは明示した範囲での確認であり，絶対的な保証ではない．Verification Notes自体は，形式検証と同等の数学的保証を与えない．実験の実施・再現だけを確認済みとしても定理全体を確認済みにはしない．反例探索が不成功というだけでは元の主張の確認にはならない．
同じ対象に問題と未確認部分が共存する場合は `問題あり` とし，内訳を記す．範囲や結果が異なる部分は必要に応じて行を分ける．未解決の疑義は確定した誤りと区別する．

## 形式検証結果の参照（任意）

形式化とカーネル検査は別Skillの責務とし，ここでは外部の成果・報告を参照する．参照した事実と，その内容を確認できたことを区別する．必要に応じて次を `Evidence`・`Dependencies`・`Not settled` にまとめる．専用カードや表は必須ではない．

- 結果の保存先・報告者・コードや成果物の版・対象宣言を特定する．環境・検査条件・カーネル受理は参照元が報告した内容とし，情報の有無・確認根拠を示す．本Skillで検査を実行したと記さない．
- 形式化された命題・定義と原稿の命題・仮定・結論の対応，検証範囲，追加仮定・axiom・sorry等，未形式化部分について，確認できた内容には根拠を付け，不明・未照合の内容は未確認と明示する．「報告に記載あり」と「原稿との対応をM1で照合済み」を分ける．
- 原稿との対応が部分的なら，外部で形式検証済みと報告されていても原稿全体のResultを確認済みにしない．追加仮定や未確認事項は主要定理一覧にも反映する．原稿・形式化・参照結果の版が変われば，対応と適用範囲の再確認が必要か調べる．

## 候補と主要定理の一覧

- writing・reviewが渡す未着手候補は `to_verify.md` の `Active candidates` に対象・版・疑問・記録する価値・次の確認を記し，`candidate` とする．Vや予定のMは判明した範囲で付ける．候補の処理状態と数学的なResultは別である．
- 処理後は `Resolved candidates` に日付，`card-created`・`recorded`・`rejected`，card IDや統合・移動先，理由を残す．ここは候補の処理履歴であり，数学的に解決済みという意味ではない．短い記録だけで足りれば `recorded` とし，カード作成を強制しない．
- `index.md` または既存の中央一覧で，主要な定理ごとに版・確認範囲・方法・Result・根拠へのリンク・未確認箇所を一覧にする．未着手の主定理も未確認と示す．全補題・全項目を網羅する表は不要．一覧に根拠を複製せず，詳細記録を参照する．記号一覧は必要時だけ作る．

| マーカー | 扱い |
| --- | --- |
| TO VERIFY | 未着手の候補．証拠や確認済みを意味しない |
| TODO | 現在の正しさに関わる未解決事項．`Not settled`と中央TODOを同期する |
| TO FILL | 原文・書誌情報等の未入手・未確認 |
| SUGGEST | 説明・構成だけの改善案．correctness cardを作らない |
| Open problems | 現在の正しさを妨げない探索課題 |

## 改訂・修復・再検証

- `Paper lines`と現在の本文を比較する．一致しても，依存する定義・補題・文献の版が変われば影響を調べる．依存記録にないことだけで影響なしとしない．
- 影響するカードから主結果まで下流をたどる．旧版の根拠・Resultを履歴として保持し，現行版で再検証が必要な範囲は一覧とカードで `未確認` にする（有効な部分を分離できれば `部分的に確認済み`）．既知の問題は隠さず残す．次の確認と中央TODOも更新する．
- 表現だけの変更で主張・仮定・依存が変わらないと確認できた場合は，証明の再検証を省き，版・引用・一覧を更新して判断の根拠を `Log` に残す．差分の小ささだけで判断せず，影響不明の範囲は未確認とする．
- 元の主張を保つ補完と，仮定追加・結論弱化による修復を区別する．後者では「変更後の主張について」と明記し，下流の結果やAbstract等の数学的主張への影響を確認する．重要な方針は人間に確認する．
- 修正案・パッチ，著者の同意・保留，後のレビューでの未言及だけでは解決済みとしない．再検証後に根拠・版・Resultを記録し，未解決欄・中央TODO・主要定理一覧を更新する．依存元の証明が使えないことと，下流の結論が偽であることを区別する．
- 再利用価値のある失敗や削除された結果の有用な証拠は，障害・限界・再検討条件や削除理由を付けて保持する．

## 旧カードの移行

旧C1–C5は対象と方法が混在していたため，機械的に一対一置換しない．既存のID・証拠・履歴は保持し，カードを再利用・更新するときに具体的な対象と実施した方法を読み取り，What・How・Resultを補う．旧Categoryは履歴として残せるが，現行分類や必須欄の判定には使わない．旧記録の「確認した」だけからResultを推測しない．

| 旧分類 | 主な移行先（内容に応じて複数可） |
| --- | --- |
| C1 外部文献 | V4，適用する主張・仮定はV1，主結果への影響はV5．原文照合はM1 |
| C2 内部依存 | V3，適用条件はV1，影響範囲はV5．逐次照合はM1 |
| C3 計算・推論 | V2，主張との一致はV1．展開はM1，実験はM2 |
| C4 仮定・反例 | V1，必要ならV2．使用箇所はM1，実験はM2，反例探索はM3 |
| C5 独立確認 | 対象に応じてV1–V5．具体例・別計算はM1/M2，別証明はM4．独立性は実施条件として記録 |

旧 `Expanded step`・引用欄・`Tests`等をEvidenceとして再利用し，新しいEvidence欄への転記を求めない．旧 `\vcategory` は既存LaTeXカードの読み込み用に残し，新規カードはWhat・Howを使う．
