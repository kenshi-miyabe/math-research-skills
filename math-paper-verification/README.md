# math-paper-verification

数学論文の正しさを効率よく検証し，再確認可能な根拠をVerification Notesに残すCodex Skill．2026年10月22日「Verification Notes の提案」に関して提示された再設計指示に基づき，対象・方法・記録を分離した．配置と呼び出し例はリポジトリのREADMEを参照する．

- `SKILL.md`：制約と簡潔なワークフロー，人間への確認，参照先．
- `references/verification-checks.md`：検証対象 V1–V5，基本的な方法 M1–M4，外部の形式検証結果との接続，探索的研究との境界，任意の独立再検証．
- `references/evidence-cards.md`：Evidenceの欄，4種類のResult，候補・主要定理一覧，改訂追跡，旧分類からの移行表．
- `templates/`：Markdown・LaTeXカード，候補と主要定理一覧のひな型．
- `assets/verification.sty`：What・How・Result・Evidenceの表示と，旧カード用マクロの互換性．既存プロジェクトで新テンプレートを使う際はstyも更新する．

Lean等による形式化・カーネル検査は別Skillの責務とし，専用Skillは今回作成しない．既存の結果はEvidenceから参照し，原稿との対応・検証範囲・追加仮定等の確認済み情報と未確認情報を区別する．Verification Notes自体は形式検証と同等の数学的保証を与えない．

旧C1（外部文献）は主にV4，C2（内部依存）はV3，C3（計算・推論）はV2，C4（仮定・反例）はV1とM3へ分ける．旧C5（独立確認）は対象に応じたVとM1/M2/M4，実施時の独立性の記録に分ける．一対一の置換ではない．既存のcard ID・根拠・履歴は保持し，一括再作成しない．

## ケースA–Fによる構造の確認

以下は架空の小規模な入力に対して，対象・方法・記録・次の作業を紙上で追った確認例である．実在の引用を読んだ記録や，コード・Lean・別のAIによる検証を実行した記録ではない．実運用で同じ結果になると保証するものではない．

| ケース・入力 | What / How | EvidenceとResult，次の作業 |
| --- | --- | --- |
| A．原稿がパラメータに一様な定数を使うが，引用文では定数の依存先が不明 | V1・V4 / M1 | Locator・Source text・Notation map・Gapに原文と必要条件を照合．原文の主張だけ確認でき，一様性は不明なら「部分的に確認済み」．Not settledと中央TODOに残し，証明・重要な依存先を選択的に調べる．一様性があると推測しない |
| B．(0,1)上で f_n=n·1_(0,1/n) に各点収束だけを使って極限と積分を交換する | V1・V2 / M1（反証の確認にはM3も可） | Expanded stepに f_n(x)→0 と ∫f_n=1 を記す．主張された交換は成立せず「問題あり」．全仮定を照合し，欠けた可積分な共通優関数等の条件を調べる．修復による仮定追加を黙って行わない |
| C．全実数a,bで (a+b)^2≥a^2+b^2 という主張を整数格子で探索する | V1 / M2・M3 | Testsには範囲・列挙順・コード・実際の出力を残す設計．例として候補(a,b)=(1,−1)が得られたなら，M1で 0<2 と実数条件を直接確認して初めて「問題あり」．未実行は「未確認」，不成功でも全実数の主張を確認済みにしない |
| D．有限木の辺数の補題を外部定理なしで直接証明する | V2・V3 / M4・M1 | Expanded stepに頂点数1の基底，頂点数2以上での最長路による葉の存在，葉の除去による帰納法を置く．共有する木の定義・内部補題をDependenciesに明示．導出を完結できれば当該補題の別証明は「確認済み」．元の証明や全論文の検証済みとはしない |
| E．主定理の修復で仮定を追加し，その系が旧定理を使っている | V1・V3・V5 / M1 | 旧版の証拠・結果をLogに保持．変更後の主張，系の適用条件，主結果への依存，Abstract等をたどる．系で追加仮定を満たすか再検証するまで現行版の当該範囲は「未確認」．カード・主要定理一覧・中央TODOを同期する |
| F．論文は実数xについて x²>0 と述べるが，参照した形式化は x≠0 を仮定する | V1・V5 / M1（外部の形式検証結果を参照） | Evidenceに参照先・版・形式命題を記し，追加仮定 x≠0 の照合済み情報と，未確認の検査条件・未形式化部分等を分ける．M1で x=0 を照合すると論文の全称主張は「問題あり」．カーネル受理は参照元の報告と区別して記し，原稿の主張の保証にしない．本Skillでは形式化・カーネル検査を行わない |

いずれも対象・方法は複数選択でき，Resultは根拠が及ぶ範囲に限定される．主要定理一覧では部分的な確認と残りの未確認範囲を分け，問題を一般化の研究課題へ移して隠さない．

特定プロジェクトの古い構成例は[保存資料](../docs/examples/master-exposition.md)であり，現行の汎用規則には用いない．
