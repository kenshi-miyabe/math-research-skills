# 数学研究の探索

## 探索の例

- 既知の結果の別証明を探す．未解決問題の証明を探す．
- 予想を立てる．例や計算実験から手がかりを得たり，反例を探して主張の限界を調べたりする．
- 既知の結果を一般化する．結論を保って仮定を弱める，同じ仮定で結論を強める，仮定を強めて結論も強める，仮定を弱めて結論も弱める，といった変形を試す．
- 証明がうまくいかない理由を調べ，推論が止まる箇所や手法の障害を明らかにする．
- 似た概念を使う論文や分野を探す．似た証明技術を使う論文や分野を探し，どの議論に応用できそうかを調べる．

## 進め方と記録

プロジェクトルートに `explore/` を作り，通常は日付（`explore/YYYY-MM-DD.md`）またはトピック（例 `explore/weaker-assumptions.md`）でMarkdownファイルを作る．同じ探索を続ける場合は既存のメモに追記し，元の問いと試行の履歴を保持する．

1. 問い，対象，仮定と結論を記録する．原稿に関係する場合は版と関連する主張を添える．既知の結果を変形する場合は，元の仮定と結論から何を変えたかを記す．あわせて，試す方針と打ち切る条件（何を試したら一区切りとするか）を決めて書く．
2. 問いに合う方法を選ぶ．証明の試行が止まった場合は，行き詰まった箇所と分かった理由を記す．文献を扱うときは[文献の保存と照合](../references/source-materials.md)に従い，概念や技術の類似を見つけたら，出典と対応する定義や議論を記す．
3. 実際に試した方法と得られた結果を記録する．再現に必要なコード・入力・実行条件・出力は `explore/` に保存するか，既存の資料を参照する．反例は全仮定を満たし結論を破ることを確認する．有限探索の一致や反例が見つからなかった事実を証明として扱わない．
4. 次のいずれかで探索を終える．問いに答えが出た．予定した方針を試し終えた．問題の変更や仮定の大幅な変更など研究方針の判断が必要になった．最後の場合は先に進まず，ユーザーに相談する．

## 終わり方

メモの末尾に「結論」の節を置き，各結果を次のいずれかに分類する．

| 分類 | 意味 |
| --- | --- |
| 証明済み | 証明をメモに記載した |
| 反例確認済み | 全仮定の成立と結論の破綻を確認した |
| 数値的・有限的な根拠のみ | 計算実験や有限探索で支持されるが証明はない |
| 予想 | 根拠のある見込みだが未証明 |
| 行き詰まり | 試した方針，障害，再検討の条件を記す |
| 未着手の案 | 次に試せること |

結果を次の作業へ回す．

- 現行原稿の主張への疑義は，種別「数学」として `review/todo.md` に追加する．[指摘の管理と修正メモ](../references/issues-and-memos.md)
- 原稿に入れたい結果は，著者の承認を得てから[執筆手順](../write/workflow.md)に回す．新しく証明した結果は，本文に入れる前に[検証手順](../verify/workflow.md)にかける．

ユーザーには，結論の要約と次の一手を数行で報告する．
