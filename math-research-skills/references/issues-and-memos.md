# 指摘の管理と修正メモ

パスはプロジェクトルートを基準とする．未解決の指摘・疑義は `review/todo.md` の1か所で管理し，別の未解決一覧を作らない．原稿の修正記録は `backup_memo/` に置く．

## 指摘ID

- 形式は `R-NNN`（3桁の連番，例 `R-001`）とする．`review/todo.md` と `backup_memo/` にある既存IDの最大値の次を使い，削除した項目のIDも再利用しない．
- reviewに限らず，write・verify・exploreが見つけた項目も同じ形式で追加する．同じ箇所・同じ問題の項目が既にあれば追記し，重複させない．
- 再レビューで同じ問題が残る場合は元のIDを引き継ぎ，新しい問題には新しいIDを付ける．
- 検証カードのID（`E-…`）とは別に管理し，カードには対応する指摘IDを併記する．

## `review/todo.md` の書式

ファイル先頭に，直近のレビューの対象版・範囲・想定読者・モードを書く．各項目は次の形にする．

```markdown
## R-001
- 種別: 数学 / 読みやすさ
- 重要度: A / B（A＝理解を妨げる，B＝改善候補．文体の好み（C）は通常書かない）
- 箇所: label，ファイル・行，短い引用
- 内容: すぐに確認できない主張と確認に必要なこと，または具体的な読者負担
- 改善案: あれば指摘と分けて書く
- 状態: 未着手 / 確認中 / 資料待ち / 方針待ち / 直さない（決定と理由）
- 関連: card ID，文献ID（書誌情報は[文献の保存と照合](source-materials.md)に従う）
- 発見: 日付，作業（review / write / verify / explore），対象の版
```

## 担当

| 種別 | 担当 | 処理 |
| --- | --- | --- |
| 数学 | [verify](../verify/workflow.md) | 正誤を検証し，根拠と結果をカードに残す．原稿の修正が必要なら依頼範囲内で修正するか修正案を示す |
| 読みやすさ | [write](../write/workflow.md) | 原稿を直し，修正メモを残す |

作業中に担当外の種別の問題を見つけたら，その場で判定・処理せず `review/todo.md` に追加する．

## 処理と修正メモ

- 未解決の項目は，状態・残る疑義・次の確認を更新する．修正案や保留は未解決として扱う．
- 編集方針で直さないと決めた項目は削除せず，状態に決定と理由を書く．数学的な疑義の判定は編集上の決定と区別する．
- 解決のために原稿を修正したら，`backup_memo/<指摘ID>.md` に記録する（例 `backup_memo/R-003.md`）．指摘ID，種別，元の指摘（`review/todo.md` の項目をそのまま写す），変更箇所と変更前後の内容，修正後の版，確認結果，関連card IDを書く．
- 原稿を変えずに解決した数学的指摘（疑義が誤解だった等）は，根拠をカードの `Log` に残す．
- 解決を確認したら，カードまたは修正メモに結果を残してから `review/todo.md` の該当項目を削除する．解決済み項目の履歴は `backup_memo/` とカードで追う．
